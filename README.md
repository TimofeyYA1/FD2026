# Запуск семинара 4

1. В IntelliJ IDEA выберите **File → Open** и откройте корень репозитория (папку с этим README), не отдельный `.kt`. Разрешите импорт проекта Gradle.
2. Используйте JDK 26. Если его нет: **File → Project Structure → Project → SDK → Download JDK**, выберите 26. В **Settings → Build Tools → Gradle → Gradle JVM** выберите тот же JDK. Дождитесь синхронизации; при первом открытии нужен интернет.
3. Откройте `lesson4/seminar/tasks/Main.kt`, нажмите зелёный треугольник возле `fun main()`. Чтобы проверить свою функцию, вызовите её внутри `main`. Можно также запустить `main()` прямо в `Task01.kt`–`Task09.kt`: пример вызова там закомментирован, пока вы не решите задачу.

В терминале из корня на Windows: `.\gradlew.bat :seminar-4:run`; на macOS/Linux: `./gradlew :seminar-4:run`. Отдельный Gradle или компилятор Kotlin устанавливать не нужно. Для запуска отдельного файла из терминала замените `:seminar-4:run` на `:seminar-4:runTask05` (или укажите другой номер). Для терминала команда `java -version` должна находить JDK 26 (или укажите его папку в `JAVA_HOME`).

## Тесты семинара

**Проще всего в IDEA:** в списке запусков сверху выберите `Task01Test` (или нужный тест №2–9) и нажмите ▶. Настройка уже привязана к корню проекта и использует Gradle JVM из шага 2, а не `java` из терминала. Не нужно вручную выставлять `PATH` или `JAVA_HOME` для запуска из IDEA.

**Из терминала:** откройте терминал в корне репозитория (там, где `gradlew.bat` и `settings.gradle.kts`).

```powershell
# Windows, PowerShell
.\gradlew.bat :seminar-4:test --tests "*Task01Test"
```

```bash
# macOS / Linux
./gradlew :seminar-4:test --tests '*Task01Test'
```

Для задач №2–5 замените номер в имени теста. Для №6–9 вместо `--tests ...` укажите `-Pbonus=06`, `-Pbonus=07`, `-Pbonus=08` или `-Pbonus=09`. Если запускаете из другой папки, укажите **и** полный путь к wrapper, **и** `-p` с полным путём к корню проекта (оба пути в кавычках).

- `gradlew.bat ... not recognized` или `Gradle build ... is not part of the build`: проверьте текущую папку командой `Get-Location` и вернитесь в корень проекта.
- `JAVA_HOME ... invalid directory`: `JAVA_HOME` должен указывать на папку JDK (не на `bin` или `java.exe`). Если терминал не видит Java, можно запустить тест из IDEA с выбранным **Gradle JVM: JDK 26**.
- `NotImplementedError` или `Задача ... пока не решена`: тесты уже запустились; нужно дописать задачу.

На GitHub основные задачи проверяются при пуше в `main` и в PR в `main`. На чистом шаблоне запуск файлов работает, но тесты нерешённых задач ожидаемо красные.
